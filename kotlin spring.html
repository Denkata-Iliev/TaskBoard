🎯 What You're Building

A REST API backend for a collaborative task board. Think of it as a simplified Linear or Jira. Users belong to workspaces, workspaces have boards, boards have columns, columns have tasks. Permissions are scoped per workspace. Eventually, the board updates in real-time via Server-Sent Events.

💡 The goal is NOT to build a production app. The goal is to touch every part of the Kotlin + Spring Boot stack in a project that actually has a reason to use each feature, not just a fake CRUD exercise.

🗺️ The Big Picture

Workspace  ← top-level container, like a Slack workspace
    │
    ├── WorkspaceMembership  ← User + Workspace + Role (OWNER / MEMBER / VIEWER)
    │
    └── Board  ← a board lives inside a workspace
          │
          └── Column  ← Backlog / In Progress / Done / custom
                │
                └── Task  ← the actual work item
                      ├── assignee   → User
                      ├── comments   → Comment[]
                      ├── labels     → Label[]  (Phase 3)
                      └── activity   → ActivityEvent[]  (Phase 2)

📦 Tech Stack

Kotlin + Coroutines

The whole thing is written idiomatically in Kotlin. suspend functions everywhere, no Reactor types directly.

Spring WebFlux

Reactive web framework. Replaces Spring MVC. Needed for coroutine-native controllers and SSE support.

Spring Data R2DBC

Non-blocking database access. Like JPA but designed for coroutines. Uses PostgreSQL.

Spring Security (Reactive)

JWT authentication. Workspace-scoped authorization. A custom @PreAuthorize component.

SharedFlow → Redis (later)

Start with in-memory SharedFlow for pub/sub. Swap to Redis in Phase 4 to understand what problem it solves.

Flyway + PostgreSQL

DB migrations like you've done before. Same concept, slightly different setup with R2DBC.

🗃️ Entities

💡 R2DBC entities look similar to JPA but there are key differences: no lazy loading, no @OneToMany / @ManyToOne annotations, and no cascading. Relationships are handled manually in services. This is a feature, not a bug — it forces you to be explicit.

User

@Table("users")
data class User(
    @Id val id: UUID = UUID.randomUUID(),
    val email: String,
    val passwordHash: String,
    val displayName: String,
    val createdAt: Instant = Instant.now()
)

// Never expose passwordHash in responses. Use a response DTO.
data class UserResponse(val id: UUID, val email: String, val displayName: String)

Workspace

@Table("workspaces")
data class Workspace(
    @Id val id: UUID = UUID.randomUUID(),
    val name: String,
    val createdBy: UUID,    // User.id — just the ID, not the whole User object
    val createdAt: Instant = Instant.now()
)

WorkspaceMembership

enum class WorkspaceRole { OWNER, MEMBER, VIEWER }

@Table("workspace_memberships")
data class WorkspaceMembership(
    @Id val id: UUID = UUID.randomUUID(),
    val workspaceId: UUID,
    val userId: UUID,
    val role: WorkspaceRole,
    val joinedAt: Instant = Instant.now()
)

// Helper on the enum — checks if a role "outranks" another
fun WorkspaceRole.hasAtLeast(required: WorkspaceRole): Boolean =
    this.ordinal <= required.ordinal  // OWNER=0, MEMBER=1, VIEWER=2

New Concepts Introduced

SharedFlow

An in-memory pub/sub channel. Multiple coroutines can collect from it simultaneously. When you emit, all collectors get it.

Server-Sent Events (SSE)

A one-way HTTP connection that stays open. The server pushes data to the client whenever it wants. The client doesn't need to poll.

BoardEvent (sealed class)

A sealed class hierarchy representing everything that can happen on a board. The SSE stream emits these.

The BoardEvent Sealed Class

sealed class BoardEvent {
    abstract val boardId: UUID
    abstract val timestamp: Instant

    data class TaskCreated(
        override val boardId: UUID,
        val task: TaskResponse,
        override val timestamp: Instant = Instant.now()
    ) : BoardEvent()

    data class TaskMoved(
        override val boardId: UUID,
        val taskId: UUID,
        val fromColumnId: UUID,
        val toColumnId: UUID,
        override val timestamp: Instant = Instant.now()
    ) : BoardEvent()

    data class TaskUpdated(
        override val boardId: UUID,
        val task: TaskResponse,
        override val timestamp: Instant = Instant.now()
    ) : BoardEvent()

    data class TaskDeleted(
        override val boardId: UUID,
        val taskId: UUID,
        override val timestamp: Instant = Instant.now()
    ) : BoardEvent()

    data class CommentAdded(
        override val boardId: UUID,
        val taskId: UUID,
        val comment: CommentResponse,
        override val timestamp: Instant = Instant.now()
    ) : BoardEvent()
}

The BoardEventBus

@Component
class BoardEventBus {

    // One SharedFlow per board, created lazily when first needed
    private val flows = ConcurrentHashMap<UUID, MutableSharedFlow<BoardEvent>>()

    private fun flowFor(boardId: UUID): MutableSharedFlow<BoardEvent> =
        flows.getOrPut(boardId) {
            MutableSharedFlow(replay = 0, extraBufferCapacity = 64)
        }

    // Called from services when something happens
    suspend fun publish(event: BoardEvent) {
        flowFor(event.boardId).emit(event)
    }

    // Called from SSE controller to get the stream for a board
    fun subscribe(boardId: UUID): Flow<BoardEvent> =
        flowFor(boardId).asSharedFlow()
}

The SSE Controller Endpoint

@GetMapping("/boards/{boardId}/events", produces = [MediaType.TEXT_EVENT_STREAM_VALUE])
fun boardEvents(
    @PathVariable workspaceId: UUID,
    @PathVariable boardId: UUID,
    @AuthenticationPrincipal principal: UserPrincipal
): Flow<ServerSentEvent<BoardEvent>> {
    // Auth check: is this user a member of the workspace?
    // Then just return the flow — Spring handles the rest
    return eventBus.subscribe(boardId).map { event ->
        ServerSentEvent.builder(event)
            .id(UUID.randomUUID().toString())
            .event(event::class.simpleName)
            .build()
    }
}

🧠 Key Concepts You'll Learn

suspend functions

Functions that can pause without blocking a thread. The foundation of everything in this project.

Flow<T>

An async stream. Like a list but items arrive over time. Used for DB results, SSE, and pub/sub.

SharedFlow

A Flow that multiple collectors can subscribe to simultaneously. The in-memory pub/sub mechanism.

R2DBC

Non-blocking DB access. Similar to JPA but no lazy loading or relationship annotations.

WebFlux

The reactive Spring web framework. Controllers can return Flow and use suspend directly.

Reactive Security

Spring Security rewritten for the reactive world. SecurityContextHolder becomes ReactiveSecurityContextHolder.

Sealed Classes as Events

Model domain events as a sealed class hierarchy. Exhaustive when means you can't forget to handle a new event type.

Extension Functions on Enums

WorkspaceRole.hasAtLeast() — adding behavior to enums without modifying them.

Server-Sent Events

HTTP connections that stay open. The server pushes updates. The client just listens.

🔑 The Authorization Component

This is one of the most interesting parts. A Spring component that gets used in @PreAuthorize to check workspace-scoped roles.

@Component("workspaceAuth")
class WorkspaceAuthorizationService(
    private val membershipRepository: MembershipRepository
) {
    suspend fun hasRole(
        workspaceId: UUID,
        requiredRole: WorkspaceRole,
        principal: UserPrincipal
    ): Boolean {
        return membershipRepository
            .findByWorkspaceIdAndUserId(workspaceId, principal.id)
            ?.role
            ?.hasAtLeast(requiredRole)
            ?: false
    }
}

// Usage on a controller method:
@DeleteMapping("/{boardId}")
@PreAuthorize("@workspaceAuth.hasRole(#workspaceId, 'OWNER', principal)")
suspend fun deleteBoard(
    @PathVariable workspaceId: UUID,
    @PathVariable boardId: UUID
): ResponseEntity<Unit> { ... }
💡 The #workspaceId in the SpEL expression binds directly to the method parameter named workspaceId. This is the same mechanism you've seen in Java Spring — it's identical in Kotlin.

⚡ suspend vs Flow — When to Use Which

SituationUseWhy
Return a single thing from DB suspend fun getTask(): Task One result, done.
Return a thing that might not exist suspend fun find(): Task? Nullable return, Kotlin handles this cleanly.
Return a list from DB fun getTasks(): Flow<Task> Stream the results as they arrive instead of buffering all of them.
SSE / live stream fun events(): Flow<Event> Flow that never completes on its own — Spring keeps the connection open.
Save / update / delete suspend fun save(): Unit Side effect, no return value needed.

🏗️ R2DBC vs JPA — Key Differences

JPA (what you know)

  • @OneToMany, @ManyToOne work automatically
  • Lazy loading — related entities fetched on access
  • Cascading — save parent, children saved too
  • Specifications for dynamic queries
  • Optional<T> returns

R2DBC (what you'll learn)

  • No relationship annotations — just foreign key IDs as fields
  • No lazy loading — you fetch related data explicitly
  • No cascading — you handle deletes manually
  • DatabaseClient for dynamic queries
  • Flow<T> and nullable returns
✅ R2DBC feels more verbose at first because you're explicit about everything. This is actually a good thing for learning — you see exactly what SQL is being executed, with no magic happening behind the scenes.

🧪 Testing Strategy

Three levels of tests. Each level has a clear purpose. Don't try to cover everything with integration tests and don't try to cover everything with unit tests.

Unit Tests

Test a single class. All dependencies are mocked with MockK. Fast. No Spring context. No database.

Integration Tests

Boot the full Spring context. Use a real database via Testcontainers. Test the full request → response chain.

Flow Tests

Test async streams with Turbine. Verify that emitting events causes subscribers to receive the right values.

Unit Tests with MockK

Test service logic in isolation. This is where TDD makes the most sense — write the test before the service method.

class TaskServiceTest {

    private val taskRepository = mockk<TaskRepository>()
    private val eventBus = mockk<BoardEventBus>()
    private val service = TaskService(taskRepository, eventBus)

    @Test
    fun `should throw NotFoundException when task does not exist`() = runTest {
        // Given
        coEvery { taskRepository.findById(any<UUID>()) } returns null

        // When + Then
        assertThrows<NotFoundException> {
            service.getTask(UUID.randomUUID())
        }
    }

    @Test
    fun `should publish TaskMoved event when task is moved to a new column`() = runTest {
        // Given
        val task = aTask()  // test data builder function
        coEvery { taskRepository.findById(task.id) } returns task
        coEvery { taskRepository.save(any()) } returns task
        coEvery { eventBus.publish(any()) } just runs

        // When
        service.moveTask(task.id, newColumnId = UUID.randomUUID(), position = 0)

        // Then
        coVerify { eventBus.publish(ofType<BoardEvent.TaskMoved>()) }
    }
}

// Test data builder — keeps tests readable
fun aTask(
    id: UUID = UUID.randomUUID(),
    title: String = "Test Task",
    columnId: UUID = UUID.randomUUID(),
    boardId: UUID = UUID.randomUUID()
) = Task(id = id, title = title, columnId = columnId, boardId = boardId,
          priority = Priority.MEDIUM, position = 0, createdBy = UUID.randomUUID())
✅ Test data builders (the aTask() function above) are your best friend. They let you create test objects with sensible defaults and only override what the specific test cares about. One file called TestFixtures.kt with all your builders keeps things clean.

Flow Tests with Turbine (Phase 2)

class BoardEventBusTest {

    private val bus = BoardEventBus()

    @Test
    fun `subscriber receives event when it is published to their board`() = runTest {
        val boardId = UUID.randomUUID()
        val event = BoardEvent.TaskCreated(boardId = boardId, task = aTaskResponse())

        bus.subscribe(boardId).test {  // .test {} is Turbine's API
            bus.publish(event)

            val received = awaitItem()
            assertThat(received).isEqualTo(event)

            cancelAndIgnoreRemainingEvents()
        }
    }

    @Test
    fun `subscriber does NOT receive events for a different board`() = runTest {
        val boardA = UUID.randomUUID()
        val boardB = UUID.randomUUID()

        bus.subscribe(boardA).test {
            bus.publish(BoardEvent.TaskCreated(boardId = boardB, task = aTaskResponse()))

            expectNoEvents()  // boardA subscriber gets nothing
            cancelAndIgnoreRemainingEvents()
        }
    }
}

📋 TDD Approach for This Project

🧠 Where TDD helps most here: service logic, domain rules, the event bus. Where TDD is harder: security config, controller wiring, database setup. Don't force TDD everywhere — use it where it adds clarity.
1

Write the test first for service methods

Before writing TaskService.moveTask(), write a test: "given a task in column A, when I move it to column B, the task's columnId should change and an event should be published." Watch it fail. Then implement.

2

Write integration tests after controllers

Controllers are mostly wiring. Write the integration test after the controller is wired, but use it to verify the happy path and the key error cases (404, 403, 409).

3

Write Flow tests alongside the EventBus

BoardEventBus is pure logic with no HTTP or DB. Write the Turbine tests at the same time you write the bus — it's one of the best TDD fits in this project.
